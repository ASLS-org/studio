# Design: restyle-manual-site

## Revision (2026-11-05)

The first pass mapped Studio's colour tokens onto VitePress's default theme and built a
gradient-and-screenshot hero. The user rejected it: it looked like a generic AI theme on top of
VitePress, with poor colours and a weak home page. They asked for:

1. the **actual look and feel of Studio**: its containers, fonts, icons, borders and components
   (menu, toolbar, lists), not a recolour;
2. a **cutting-edge hero** with real 3D and effects. It doesn't have to follow the uikit, but it
   must impress;
3. **no screenshots** generated by the agent.

Choices made with the user: the hero shows **Studio's own rig, cinematic**; product visuals are
**live Studio components** (unit 2); the shell uses **Studio chrome with readable body text**.

Kept from the first pass: D1 (tokens file), D3 (theme sync), D4 (`StudioFrame` / `asls-scope`),
D5 (lazy palette), D7 (URLs from `.env`), D8 (deploy fix), the `<Video>` fix, and the removal of
unused media. Dropped: the `--vp-*` reskin as the main look, the `Home*` components and the
screenshots in `public/home/`.

## Context

- Studio's chrome: `toolbar.fragment.vue` (`uk-menu` with `menus` → `items`, a centred project
  name, BPM/playing/tap controls on the right), `patch-bay.fragment.vue` (`h3` header, `uk-list`
  with `accordion`, `filterable`, `colored`, `items: [{ id, name, color, unfold: [...] }]`), and
  `uk-widget` (header: `uk-icon` + `h3` title, optional action button, dockable body). Icons are
  SVGs in `uikit/icons/images`, coloured with `fill`.
- Tokens: `src/assets/styles/tokens.css` (dark `:root`, `[data-theme="light"]`).
- The visualizer is data-driven: `FixtureRenderer` builds fixtures from patch entries (`channels`,
  `physical`, `geometry`, `position`, `rotation`, `frame`) and re-decodes a fixture when the
  bytes of its universe `frame` change. `Visualizer` (`init()`) also builds editor helpers: a
  checkerboard floor, an infinite grid, axes, OrbitControls, TransformControls and Stats. It
  loads quality from `localStorage`.
- VitePress renders pages on the server at build time, so WebGL, `window` and `document` only
  exist in `onMounted` and in dynamically imported client modules.

## Goals / Non-Goals

**Goals:** a manual that reads as a Studio panel; a hero that shows Studio's real renderer at
its best; no agent-made screenshots.

**Non-Goals:** live widget previews and the home page's product sections built from them
(unit 2); sidebar restructuring (units 3–4); changes to the app's own visualizer behaviour.

## Decisions

### D1. Split tokens into `src/assets/styles/tokens.css` (done)
Custom properties only. `global.css` `@import`s it, and the manual imports it. The app was
verified pixel-identical outside the animated visualizer.

### D2. A custom VitePress layout made of Studio components ("Studio shell")
`theme/Layout.vue` replaces `DefaultTheme.Layout`, keeping VitePress routing, `<Content>`,
`useData()` for the sidebar and nav config, and local search (`VPLocalSearchBox`, opened from
the toolbar). The VitePress default-theme CSS is no longer the look:

| Region | Built like | Components |
|---|---|---|
| Top bar | Studio's toolbar: the manual's sidebar sections as menus (GETTING STARTED, INTERFACE, MODIFIERS, WORKFLOW), the page title centred like the show name, and on the right SEARCH, DARK/LIGHT, GITHUB as toolbar buttons | real `uk-menu`, `uk-button`, `uk-icon` |
| Left panel | The patch bay: `h3` "MANUAL" header, a filterable accordion list with one coloured entry per section and its pages unfolded under it, the current page selected | real `uk-list` |
| Page | A `uk-widget`: header with the page's icon (frontmatter `icon`, default by section) and uppercase title, the content as the body | real `uk-widget` |
| "On this page" | A second, narrower `uk-widget` with the h2/h3 outline as list items | `uk-widget` + `uk-list` |
| Footer | Prev/next as two toolbar-style buttons, plus the license line | `uk-button` |

Prose (`theme/prose.css`, under `.studio_prose`): Roboto, 15px, line height 1.65. Headings use
Studio's typographic system (h2 = 16px Roboto-Regular like the app, with a separator; h3 = 12px
Roboto-Bold uppercase like widget headers). Tables look like Studio lists (row separators in
`--secondary-dark`, 12px uppercase header row). Code uses `--primary-dark`. Custom blocks look
like Studio popups (header bar + body). Links use `--accent-light-blue`. The whole shell sits on
`--primary-dark` with panels in `--primary-light`, and 1px `--primary-lighter` borders between
regions, as in the app.

Where a uikit component's API doesn't fit a docs need (`uk-list` selection driving routing,
for example), the shell wraps it and maps events (`select` → `router.go(link)`). It never forks
the component's CSS. If a component has a side effect that conflicts with the docs (global
`keydown` listeners in `uk-list`/`uk-menu` grabbing typing in search), the fix is a minimal opt-out
prop in the component, or the shell stops propagation. Each case is noted in the tasks.

Narrow screens (< 960px): the left panel becomes a drawer opened from a MANUAL toolbar button,
and the outline widget is hidden.

*Alternative rejected:* keep reskinning `DefaultTheme`. That was the first pass, and it reads as
VitePress whatever the colours.

### D6. Hero: Studio's visualizer in a showcase mode, driven by a synthetic rig
- **Renderer.** `new Visualizer(canvas, { showcase: true })`. The option, added to
  `visualizer.js` and off by default so the app is unchanged, skips Stats, the grid, the axes,
  OrbitControls, TransformControls and the checkerboard (a dark matte floor instead, still a
  lighting receiver). It also skips the quality and `localStorage` writes and takes a fixed
  quality passed in. The hero owns the camera.
- **Rig.** No `Show`, no `Live`. The hero loads one moving-head profile through the fixture
  library (the demo show's MAC Aura, or a generic GDTF moving head if that's simpler to load) and
  builds patch entries in code: two curved trusses of about 8 heads plus a floor row of about 6,
  all on one universe `frame` (`Uint8Array(512)`) that the hero owns.
- **Choreography.** Each animation frame (`AnimationManager`), the hero writes pan, tilt,
  dimmer, colour and gobo bytes into the frame without allocating, and calls `invalidate()`:
  - pointer: raycast to the floor plane; heads aim at that point with an eased lag (≤ 0.5 s);
  - idle: a slow Lissajous sweep plus a fan, taking over 2 s after the pointer leaves;
  - beat: 120 BPM; colour steps through Studio's accent palette (violet, blue, pink, teal,
    gold) every bar, with a dimmer accent on each beat and a white flash every 4 bars;
  - scroll: progress 0 → 1 over the hero's height (sticky, 200vh) moves the camera along a
    spline from a low front view, through the trusses, to a top-down view of beam footprints,
    then the page continues.
- **Look.** Haze and exposure set for drama (dense haze, high exposure). Medium quality on
  desktop, Low on mobile or with `deviceMemory` ≤ 4, render scale 0.75. A CSS vignette and
  grain over the canvas. The headline uses large type with the name in Studio's
  violet → blue accent gradient.
- **Lifecycle.** The renderer is created in `onMounted` through a dynamic `import()` (never
  during the server-side build). Rendering pauses with an IntersectionObserver and
  `visibilitychange`, and everything is disposed on unmount.
- **Fallbacks.** With `prefers-reduced-motion`, one frame is rendered with a fixed pose and
  rendering stops. Without WebGL, a CSS backdrop (radial accent glows on `--primary-dark`)
  stands in. Neither path uses an image file.
- **Cost.** The same per-frame cost as the app's visualizer for about 22 fixtures at Medium. The
  choreography writes about 22 × 8 bytes per frame into a preallocated buffer.

*Alternatives:* a bespoke Three.js scene (more freedom, but not Studio's renderer, so it would
be marketing rather than product); a pre-rendered video (rejected: no generated media, and it
can't react).

### D2 revision (second review, 2026-11-05)
The toolbar menus and the centred page title were redundant and are gone. The accordion patch
bay read as gimmicky: the navigation is now `shell/ManualNav.vue` (filter, section labels,
`uk-list-item` rows in a new opt-in `large` mode added to the uikit) and the outline is

code, accent list markers, the hero's live dot) is removed.

### D2 revision (third review, 2026-11-06)
No filter field and no separators in the navigation; section titles carry an accent dot and the
current page takes its section's colour. The page header widget is gone (a section kicker sits
above the h1). Content is back on `--primary-light`, with tables, callouts, code and quotes as
darker rounded panels and a modern h1–h6 scale. The outline is titled like the navigation and
highlights the section in view in the section's colour. The toolbar is 48px. Prev/next are
custom cards, not stock buttons.

### D2 revision (fourth review, 2026-11-06)
Nothing glows (dots, callouts, kicker, hero button). Navigation sections are separated, titles
bold uppercase above lighter page rows, and the current page is tinted with its section's colour.
The outline is a plain list without highlighting. Prev/next cards are light. A Studio-style app
footer (brand, version from the last release tag, license, credit) closes every page, including
the home page. Tables lay out as real tables on wide screens and scroll sideways on phones.

### D2 revision (fifth review, 2026-11-06)
No gap or separator between navigation sections. The outline writes the section in view in the

block (logo + search = 280px, aligned with the navigation's border); the toolbar's right side

### D2 revision (sixth review, 2026-11-06)
The content bar is a section of the toolbar (between search and the actions), on the home page
too (theme only); the language select was dropped until translations exist; on phones its theme control moves to the top of the page drawer.
The outline's title has no dot. Tables have no hover styling; tables, callouts, code, quotes and

### D6 revision: the home page story (2026-11-06)
The hero is remade as a scroll story on a four-fixture stage: each chapter (Patch, Control,
Program, Sequence, Output) moves the camera, plays its part of the show, and slides up a modifier
bar with the app's real widgets running on the same DMX frame (channels, colour picker, pan/tilt,
cue pool, chase timeline) plus a live universe view. No text gradients, outlined pills or
coloured shadows. The home content below became Get started + resources.

### D6 revision 2: hero → scene morph, floating UI (2026-11-06)
The story opens on a bold 2D hero with no scene; scrolling morphs it into the stage (hero lifts,
blurs and fades; the stage opens as an iris while the camera dollies in; nothing renders before).
The widgets float over the scene as cards with scroll-linked motion and parallax instead of a
modifier bar; the copy is numbered and hands over cleanly between chapters; a slim progress rail
replaces the chapter index.

### D6 revision 3: brand, liquid reveal, widgets in the scene (2026-11-06)
The hero carries the official logo lockup. The morph is a blur/fade/step-back of the hero over a
liquid WebGL reveal (domain-warped noise dissolving a dark cover). The widgets live in the 3D
scene through a CSS3D layer: anchored per chapter at 1:1 scale, tilted, drifting, translucent
(Studio's surface tokens redefined with alpha inside the panel), still live DOM. Copy alternates
sides per chapter.

### D6 revision 4: quality, snapping, display-only panels (2026-11-06)
The stage renders at the device pixel ratio (max 2) with the visualizer's Auto quality instead of
a fixed Medium at 0.75. Scrolling settles on chapters with an eased glide. Panels are inert; a
flat blur layer clipped to each panel's projected outline blurs the scene behind it (backdrop
blur can't work inside CSS 3D). Copy sits on a feathered frosted pool.

### D6 revision 5 (2026-11-06)
Guides-only rendering (no volumes, no surface light). Chapter snapping was tried (settle-snap,
then wheel stepping) and dropped: free scrolling read better. The pointer tilts the stage's
camera only. The sections under the story were removed; the app footer follows the story.

### D6 revision 6 (2026-11-06)
Native proximity scroll snapping at each chapter. Chapter copy is absolute in the page and
scrolls natively over the pinned stage. The pointer tilt no longer moves the widget panels
(rendered from an untilted camera).

### D6 revision 7: the scroll drives the show (2026-11-06)
Each chapter has its own scroll length and the position within it is the show's time: scrolling
plays, scrolling back rewinds, stopping holds. Chapter changes are immediate (camera glide in
real time, quick crossfade). Snapping is gone; copy is back on screen for its whole chapter.

### D6 revision 8: relative transitions, capped speed, autoplay (2026-11-06)
Each chapter plays its show over 82% of its scroll, then a scroll-driven transition moves the
camera and hands the copy and panels over to the next chapter. The story position eases towards
the scroll with a speed cap so fast scrolling stays readable. Autoplay per chapter; Back to top
at the end; no footer on the home page.

### D6 revision 9 (2026-11-06)
Constant-pace following (no velocity: shows at 2× real time, transitions ~0.7 s), long jumps
glide. The last chapter autoplays on a real-time loop; Back to top is centred at the bottom.

### D6 revision 10 (2026-11-06)
Cue and chapter changes crossfade DMX values (16-bit pan/tilt). The page is held within a
quarter chapter of the story during gestures (no momentum pile-up). A persistent scroll cue on
every step, replaced by Back to top on the last.

### D6 revision 11 (2026-11-06)
The story ends on a final hero mirroring the first (liquid cover back over the stage, hero in),
with Download / Read the manual / Replay; Output has no CTAs. Scene cues ease in over their
duration.

### D6 revision 12 (2026-11-06)
Scenes no longer ease in (they start at level; cue changes still crossfade). Sunset (red to gold
fan) replaces Hits. Output is halved (75vh) and hands straight over to the final hero (70vh) as
its copy fades. Output shows its progress bar. Replay sits under the CTAs as a text button.

### D6 revision 13 (2026-11-06)
Scene cues fade in as relative Studio scenes: from the previous cue's last values, ease-in across
the cue's whole duration (effects keep the short crossfade). Autoplay is one global toggle that
plays every chapter in turn up to the final hero. Output no longer autoplays: it scrubs with the
scroll, and its show is halved (5 s).

### D6 revision 14 (2026-11-06)
Scene fades use a cubic ease-in-out; the cue pool's first scene fades from the control chapter's
last frame, and the chase's first cue from its last. A Next button beside Autoplay skips a
chapter. The final hero arrives over the last 45% of Output while its show runs, and is complete
when the show ends.

### D9. Home page below the hero (superseded: removed in revision 5)
Short sections built from the same Studio components as the shell (widgets with icon headers):

## Risks / Trade-offs

- [`uk-list` / `uk-menu` assume app context (global key handlers, `$route`)] → wrap and map
  events in the shell. A minimal prop is added only if unavoidable, and noted in tasks.
- [VitePress features lost by dropping the default layout (mobile nav, outline, prev/next,
  search UI)] → each is rebuilt in the shell (search reuses `VPLocalSearchBox`).
- [The hero is heavy for a landing page] → dynamic import after first paint, quality tiers,
  pause off screen, fallbacks. Measure the transferred size and frame time in tasks.
- [Showcase option touches app code] → off by default, guarded `if` branches only; verify the
  app's visualizer is unchanged against the before-screenshots.
- [Fixture profile loading in the manual] → if the fixture library can't load outside the app,
  the hero embeds a minimal channel list for one moving-head mode (data, not a screenshot).
