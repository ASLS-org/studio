# Maintaining the AI context

The context is code. A stale rule is worse than none, so update it in the same PR as the change
that made it stale.

## What lives where

| File | Holds | Loaded |
|---|---|---|
| `CLAUDE.md` (root) | commands, architecture map, cross-cutting rules, traps, workflow | every session |
| `src/models/DMX/CLAUDE.md`, `src/views/CLAUDE.md`, `src/plugins/visualizer/CLAUDE.md`, `src/electron/CLAUDE.md` | the map and invariants of that folder | when working in that folder |
| `.claude/skills/<name>/SKILL.md` | step-by-step procedures and checklists for one kind of task | on demand, matched by `description` |
| `openspec/config.yaml` | project context and per-artifact rules for proposals, specs, design, tasks | every OpenSpec command |
| `.claude/settings.json` | shared permissions and hooks | every session |
| `openspec/specs/**` | behaviour requirements. **Not** AI context: maintained through OpenSpec archive | n/a |

Generated by `openspec init` / `openspec update` (don't hand-edit; re-run `openspec update`
after upgrading the CLI): `.claude/skills/openspec-*`, `.claude/commands/opsx/*`.

## Triggers: update when a change…

- adds, moves or renames a top-level folder, singleton, pool, plugin or entry point → root map +
  folder `CLAUDE.md`
- adds or changes an npm script, Node version, build target or dependency with its own API
  (three, @asls/wsc-*, electron, vue) → root "Commands" / the related skill (bump the version
  baseline in `wsc-output`)
- introduces or retires a convention, pattern or invariant → the folder `CLAUDE.md`, or
  `code-quality`
- fixes a bug listed under "Known issues" or "Known traps" → remove the entry
- reveals a trap that cost time → add it (one line, with the fix)
- adds, moves or renames a view (fragment, modifier, widget, popup), a manual page or a live
  preview preset → the coverage map in `user-manual` § Coverage map
- changes the branch, PR or release flow → `git-collaboration`
- changes the domain vocabulary or the OpenSpec capability list → `openspec/config.yaml`

No update for routine features that follow existing patterns.

## Writing rules

- Lean: root `CLAUDE.md` ≤ ~120 lines, folder files ≤ ~60, skills ≤ ~150. Cut before adding.
- State facts that can't be cheaply derived from the code: invariants, why, traps, procedures.
  Don't paste code that's already in the repo; point to the file.
- Imperative, specific, verifiable ("register with `Live.add` and pair with `Live.remove`"), not
  vague ("be careful with animations").
- Date volatile facts ("as of 2026-11-03") and version-pin external APIs.
- One home per fact. Link to it from elsewhere instead of duplicating it.
- Skill `description` = what it covers + when to use it, with the trigger words a request would
  contain. The description is what makes the skill load.

## Procedure

1. List what the change made stale: `git diff develop --stat` plus the triggers above.
2. Edit the smallest set of files. Remove stale lines rather than appending corrections.
3. Check that every path, script and symbol you mention still exists:
   `ls <path>`, `npm run | grep <script>`, `grep -rn <symbol> src`.
4. `openspec validate --all` if `openspec/config.yaml` changed.
5. Commit as `docs(ai): ...` or alongside the change. List it in the PR's "AI context" line.
